Everything converges at D1-03 (integration) then CP1. If behind at 15:50 drop: OSV cross-check → typosquat → dagre polish → React graph (use Dev5's static viewer).

One finding's journey across all five devs

  1. Dev5 pinned Juice Shop at a commit and supplied backup lockfiles + golden expectations.
  2. Dev2 copies the repo to a work dir, resolves lockfiles with --ignore-scripts, runs Syft → sbom.cdx.json, builds the graph (origin + integrity per node).
  3. Dev2 runs Grype → a CVE finding on a transitive package with fix versions; Dev4's detectors add an unpinned-CI finding and a typosquat (ngy-cookie); the diff tool fills changes.json.
  4. Dev1's detection agent dedupes, attaches dependency_paths from Dev2's paths_to(), stores findings (each citing evidence IDs).
  5. Dev4's initial_risk gives a rule-based band; Dev1's evidence analyst has Claude explain it, then grounding labels every claim VERIFIED / INFERRED.
  6. Dev1 writes graph/summary/trace; Dev3's UI renders header strip, highlighted vulnerable path, findings list with badges, agent trace.
  7. Day 2: Dev4 scores (EPSS/KEV/reachability) → Dev1 remediation plan → Dev3 approval panel → human approves → Dev2 sandbox validates → Dev4 report → Dev3 shows before/after.

How it works inside

1 · The run driver (graph/workflow.py)

  1. run() makes runs/run_<ts>/, AuditLog, JsonStore, ToolContext, LLMProvider.from_settings; registers a RunContext in a module dict (graph/state.py) keyed by run_id.
  2. LangGraph state is JSON-only (run_id, status, sbom_evidence_id, graph_evidence_id, finding_ids, errors; lists use operator.add reducers) so a checkpointer can persist it later.
  3. Nodes fetch live objects with get_ctx(run_id). Edges: START → discovery → route_after_discovery → detection → route_after_detection → evidence_analyst | END. Each route function is Python and emits a decision event with its reason.
  4. A finally block always writes graph.json, changes.json, run_summary.json, runs/LATEST — a crash still leaves viewable output.
  5. build_graph_json merges Dev2's graph with findings: sets risk (max initial_risk) and finding_ids on nodes; creates pseudo-nodes ci:/image:/config: (and edges from the project root) for non-package findings.

2 · Tool registry (tools/registry.py)

BINDINGS maps agent → ordered list of (name, "module:function"). resolve() imports lazily — a not-yet-written Dev2/Dev4 module raises ToolUnavailable, which call_tool logs and skips. That is how Dev1 could finish and test the pipeline before other devs' code landed (tests use tests/integration/fake_tools.py). After a tool returns, evidence is stored, artifacts merged, and work_dir/sbom_path/graph promoted onto ToolContext so later tools see them.

3 · Discovery and detection agents

  • Discovery: runs the 4 discovery tools in order; if workspace fails, scans the target in place read-only; collects sbom/graph evidence ids; emits stats + handoff.
  • Detection: runs grype, osv, 4 detectors, changes. dedupe() keys CVE findings by (purl, ID) for vuln_id and every alias — first seen (Grype) wins, later duplicates merge evidence ids, aliases, fix versions, CVSS, range. Fills dependency_paths via graph.paths_to(purl, 5). Stores findings.

4 · Evidence analyst (LLM) — the one real LLM agent today

See the A–Z notes §8 for the sequence diagram. Key mechanics: rank by rule risk → top 40 to the LLM in batches of 8 on 4 threads → prompt built from finding view + evidence view, each wrapped via untrusted.wrap (redact + neutralise </data> + injection scan) → strict JSON schema → parse_batch with one repair retry → ground_assessment → update Finding (initial_risk, initial_risk_source, explanation, claims, status=assessed). Any LLM failure falls back to rule_risk.

5 · Guardrails & LLM provider

  • redact.py: 9 regex families (private key, Anthropic/OpenAI/GitHub/Slack/npm/AWS tokens, JWT, password= assignments) → [REDACTED:name]; redact_obj for dict/list payloads (used by audit).
  • untrusted.py: wrap() + SYSTEM_RULE + injection regex.
  • grounding.py: schema classes (RawBatch), ground_assessment implementing G4.2/4.3/4.4/4.6.
  • file_read.py: deny-lists, outside-root guard, 64 KB cap, redaction.
  • provider.py: backends + LLMProvider with SHA-256 cache keys; replay never builds a backend.

6 · Audit (core/audit.py)

emit(agent, type, summary, **kw) redacts data, appends an AgentEvent to trace.jsonl under a lock, mirrors tool/LLM/guardrail/error events to audit.jsonl, and echoes a coloured line to stderr. JsonStore is append-only for evidence (second write raises), atomic tmp-rename for findings.json, and rejects findings that cite unknown evidence.

How it works inside

Discovery chain

Graph build details

  • Primary source: CycloneDX components + dependencies → networkx.DiGraph, node id = purl. If dependencies are empty/partial (Syft sometimes gives none), build edges from package-lock.json packages and record which source was used in the evidence.
  • Per node: direct (listed in manifest), scope prod/dev (dependencies vs devDependencies), project (root/frontend), origin (lockfile resolved URL), integrity (sha512).
  • paths_to(purl, max_paths=5) enumerates simple paths from roots — this is what turns "lodash has a CVE" into "express → body-parser → … → lodash".
  • stats() → components/direct/transitive/projects (feeds the header strip). Two roots: root and frontend/.

Scanners → Findings

grype sbom:<file> -o json parsed into Finding(category=cve, vuln_id, aliases, cvss, severity, fixed_versions, affected_range, component_purl); npm advisories are often GHSA-only so aliases (CVE) are kept for EPSS/KEV later. Raw scanner output is stored as an Evidence(kind="scanner_output") with sha256. OSV-Scanner (osv-scanner scan source -L sbom.cdx.json) is the cross-check; Dev1's dedupe merges both.

How it works inside

Graph rendering rule (§4.3)

1,500 nodes won't render legibly. The UI draws only: roots, direct dependencies, nodes on a path to a finding, and non-package pseudo-nodes (ci:, image:, config:); everything else collapses into a count on its parent. dagre lays it out left-to-right; node colour = max risk; clicking a node highlights its path and opens a side panel with origin and integrity. Mocks must be realistic size so performance problems appear early.

Trace list

Reads trace.jsonl (one AgentEvent per line) and colours by agent role: supervisor, discovery, detection, evidence_analyst, guardrail. Shows hand-offs and the supervisor's decision lines — this is the main "this is agentic" proof for judges. Later fed live via SSE.

Approval panel safety rules

  • Buttons disabled until action, evidence, diff, risk reduction, compat hint, rollback and claims have all loaded.
  • Reject / Accept risk require a comment.
  • Decision body includes plan_hash; backend rejects a mismatch (G5.1), so a stale plan can't be approved.
Show-it proofs: mock data in npm run dev · click node → path highlighted, 1,000-node mock < 2 s · all panels render · real Juice Shop < 2 s · curl returns real data · trace streams during a run · approve via API resumes a stub run. Fallbacks: Dev5's static HTML viewer and screenshots in docs/cp1/.

How it works inside

Typosquat detection (similarity.py)

For each dependency name, compare to the popular list: Damerau-Levenshtein distance ≤1–2, minimum name length 5, a popularity gap (candidate not itself popular), swapped-character and -js-suffix checks. ngy-cookie vs ngx-cookie = distance 1 ⇒ finding. Exact popular names are never flagged. False-positive count on Juice Shop deps is reported.

CI & Dockerfile adapters

github_actions.py parses workflows and finds uses: refs not equal to a 40-char hex SHA → unpinned_ci; dockerfile.py finds FROM lines without @sha256: → untrusted_image. Each finding has file + line + excerpt evidence — which Dev1 turns into ci:/image: pseudo-nodes in the graph.

The scoring engine (pure function)

Each factor carries value, tier, unknown, label, evidence_ids: values from tool evidence are VERIFIED; any value the LLM proposes (only exposure when signals are unknown) is INFERRED. The weights are the team's choice — say so openly. Raw EPSS is ≈0 for most CVEs, so the percentile is used.

Threat intel (threat_intel.py)

  • epss_lookup — api.first.org/data/v1/epss?cve=… (≤100 CVEs per call); kev_lookup — CISA KEV JSON; osv_query(purl); registry_metadata(purl) (deprecated flag, maintainers, repository, engines); safe_version_lookup(purl, vuln_ids) = lowest version fixing all.
  • All calls: disk cache + throttle; GUARDIAN_OFFLINE=1 returns cache only — keeps the demo working without Wi-Fi and avoids hammering public services.
  • Each result becomes Evidence (kinds epss, kev, osv, registry_metadata) so Dev1's grounding can verify claims against them.
