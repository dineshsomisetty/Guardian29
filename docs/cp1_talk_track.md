## Likely judge questions (short answers)

| Question | Answer (who) |
|---|---|
| **Why agents, not one script / one prompt?** | Each stage has a role, its own tools and a hand-off with evidence ids; a supervisor makes routing and budget decisions that are logged. That lets us loop (re-plan when validation fails) and stop at a human gate tomorrow. Discovery and detection are deterministic *tool agents* on purpose — facts must not be generated by a model. (Dev1) |
| **Why LangGraph?** | Explicit state graph with conditional edges for the supervisor, loops for re-planning, built-in interrupt + checkpointing for the human-approval step on Day 2. (Dev1) |
| **How do you control hallucination?** | The LLM never produces facts: it only explains and suggests an initial risk, and must cite evidence ids. Grounding is code (`guardian/guardrails/grounding.py`): unknown evidence id → claim rejected; CVE/GHSA/purl not present in the evidence → rejected; VERIFIED only when the claimed field/value matches the cited evidence; uncited claims removed. Untrusted text goes to the model only inside `<data>` blocks. Reply shape validated by our own Pydantic schema (DeepSeek JSON mode). (Dev1) |
| **Why Syft and Grype?** | Syft: one SBOM tool for directories and images across ecosystems, CycloneDX + purl output. Grype: scans that SBOM, gives fix versions. OSV-Scanner as a second source cross-checks misses. All three pinned (Syft 1.57.2, Grype 0.122.1, OSV 2.7.1) and SHA-256 verified on install. (Dev2) |
| **Why `--ignore-scripts`?** | `npm install` runs `preinstall`/`postinstall` scripts from any package in the tree — that is exactly how supply-chain malware executes. `--package-lock-only --ignore-scripts` resolves the full tree without downloading tarballs or running code. Anything that must execute (build/test) runs later in a Docker sandbox with `--network none`. (Dev2) |
| **How is the initial risk decided?** | Rule first (`guardian/core/scoring.py`): CVEs by CVSS band (≥9 critical, ≥7 high, ≥4 medium, else low; scanner severity if no CVSS), lowered one step for dev-only scope; non-package categories have defaults (typosquat high, CI/image/lockfile medium). The evidence analyst can then adjust it with a cited explanation; the finding records whether the risk came from `rule` or `llm`. Day 2 adds EPSS, KEV, reachability, exposure. (Dev1/Dev4) |
| **How are typosquats detected?** | Direct dependency names (current and legacy manifests) are compared with a list of ~340 popular npm names: Damerau–Levenshtein distance 1 (names ≥ 5 chars) or 2 (≥ 10 chars, incl. swapped letters), or a popular name plus `-js`/`js`/`.js`/`node-` affix. A name that is itself popular is never flagged. `ngy-cookie` → `ngx-cookie` (distance 1); `epilogue-js` → `epilogue` (suffix). (Dev2/Dev4) |
| **How do you get origin + integrity with no lockfile?** | We resolve the lockfile ourselves; every `packages` entry has `resolved` (registry URL) and `integrity` (sha512). The graph's edges come from that lockfile using Node's resolution rule. (Dev2) |
| **What stops the agent from changing code on its own?** | Nothing is changed at CP1. From Day 2 every remediation plan stops at a human approval (approve / reject / accept-risk with comment), bound to a hash of the plan. No auto-merge, no push. (Dev1) |
| **Secrets?** | Keys only from env; the `file_read` tool denies `encryptionkeys/`, `ctf.key`, `.env*`, `*.pem`, `*.key`; `serve-runs` refuses the `/work/` copy of the target. (Dev1) |
